## 2. 개선 전략 (7가지)

**전략 1. 개요를 그림과 표로 다시 연다** (원칙 4, 피드백 1.1)
- 맨 위 대표 화면(`cover.png`) 아래에 시연 영상 링크.
- 소개 한 문단 + **목표 경험**("우리가 같이 운전하고 있다") + **개발자 목표**("네트워크 라이브러리에 맡기지 않고 서버 통신을 직접 구현").
- 1.1의 bullet 4개와 § 링크는 지우고, 그 자리에 SHIFTER식 **"핵심 / 부딪힌 문제 / 이렇게 풀었다"** 표를 둡니다. 행은 서버 구조 · 지연 누적 · 미니게임 판정 정도.
- 팀장 역할은 팀 구성 표 아래 한 문장으로만(자세한 리딩은 Hive Purge 문서에서 다룸).

**전략 2. 장을 "네 명이 같은 것을 보게 만드는 일" 단위로 다시 나눈다** (원칙 1·2)
- 2장 "전체 구조"를 해체합니다. 구성도와 "서버를 직접 만들 것인가"는 서버 장으로, "물리를 어디서 계산하는가"와 입력 검사는 차량 장으로 옮깁니다.
- 2.3 "첫 버전에서 확장한 것" 표는 서버 장 첫머리에 한 문단 + 짧은 표로 줄입니다(수업 샘플에서 출발했다는 사실은 남깁니다).
- 3.1 접속 시퀀스 그림은 지우고 두 문장으로(슬라이드 목차에서도 "설명만 있는 곳"으로 뺀 부분).

**전략 3. 플레이 장에서 용어를 먼저 정리한다** (원칙 3)
- 역할 표 옆에 **용어 표**: 방 코드 · 호스트(핸들 담당 클라이언트) · 비호스트 · 경유지 · 미니게임 담당자.
- 한 판의 흐름은 플로차트 대신 SHIFTER식 **그림 표**(단계 이름 / 화면 / 짧은 설명)로. 화면 캡처가 없으면 위→아래 플로차트(TB)로 두고 되돌아오는 화살표는 "경유지마다 반복" 한 줄로 대신합니다.

**전략 4. 결정은 "질문형 절 제목 + 표 1 + 문단 1"** (원칙 11·13)
- "고민과 선택 ①②③" 번호, "결정 대상" 인용, `[최종 결정]`·`[감수한 대가]` 라벨을 지웁니다.
- 제목 (안):
  - ① → **서버를 직접 만들 것인가**
  - ② → **차량 물리를 누가 계산하는가**
  - ③ → **상태 메시지도 순서대로 보낼 것인가** (지금 "지연을 어떻게 끊을 것인가")
- 비교 표의 칸은 키워드로 줄이고, 긴 설명은 표 아래 bullet로 내립니다.
- Netcode for GameObjects 참고 인용은 ①의 표 아래 한 줄로.

**전략 5. 모든 절을 그림으로 연다** (원칙 7·20)
- 이미지 자리 7개를 절 맨 앞으로 옮기고, 캡션은 그림 바로 아래 기울임 한 줄.
- 지금 `images/`에는 `cover.png`만 있습니다. 촬영목록(`_intake/촬영목록.md`) 순서대로 찍어 오셔야 그림 → 주장 순서가 완성됩니다. 찍기 전까지는 자리 표시만 앞으로 옮겨 둡니다.
- 지연 장은 GIF가 결과(수정 뒤)라 앞에 둘 수 없으면, **수정 전 지연 GIF**(액셀을 누르고 한참 뒤 움직이는 화면)를 새로 찍어 장 첫머리에 두는 것을 제안합니다.

**전략 7. 회고는 목표 → 결정 묶음 → 아쉬움 → 배운 점** (원칙 4·6)
- 목표 표: 목표 경험 · 개발자 목표를 "구현해 볼 수 있었다"로 받아 줍니다(4인이 지연 없이 한 차를 운전, 접속·씬·상태/이벤트·판정을 직접 구현).
- 결정 묶음 표. 후보 질문: **"네 화면이 같다는 것을 누가 보장하는가"**
  - 씬 전환 → 서버 한 곳 / 미니게임 담당자·판정 → 서버 / 접속 ID → 서버 / 차량 물리 → 호스트(대가: 서버가 값을 검증하지 못함 → 최소 검사) / 상태는 최신값만(대가: 송신·서버·수신 세 곳 수정)
- 내비게이션을 기어 → 브레이크로 옮긴 플레이 테스트 결과는 튜토리얼·역할 쪽 결과로 한 줄.
- 7.1 일정 표는 칸을 "~다"로 고치거나 지웁니다(슬라이드 목차에서도 뺀 부분).
- 아쉬운 점 ①(미니게임 한 클래스)·②(빌드에서야 발견)는 라벨 없이 문단 하나씩 + "지금이라면" 인용(원칙 12).
