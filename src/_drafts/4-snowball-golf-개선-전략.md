## 2. 개선 전략 (7가지)

**전략 1. 가이드 5단 틀을 버리고 "만든 순서" 대로 장을 나눈다** (원칙 1·2)
- 이 프로젝트의 내용은 **컨셉 → 기획서 → 구현 지시 → 플레이·수정 → 바뀐 기획** 순으로 흘렀습니다. 장도 이 순서를 따릅니다.
- AI 작업법은 따로 장을 두지 않고, 각 단계 안에서 "그때 이렇게 요청했다"로 녹입니다. 그러면 3.1처럼 작업법 절에 게임 컨셉이 들어가는 어긋남이 없어집니다.
- 결정은 그 결정이 일어난 장으로 옮깁니다. 기획/구현 대화 분리는 기획서 장, 코드 검토 범위는 플레이·수정 장, 파괴 연출·노란색 표시는 "플레이가 바꾼 기획" 장.

**전략 2. 개요를 그림으로 열고 짧게 끝낸다** (원칙 4·22, SHIFTER)
- 맨 위 대표 GIF(`loop_overview.gif`) → 소개 한 문단 → 목표 경험 → 개발자 목표(빠른 프로토타입으로 세 질문에 답하기).
- `《》` 라벨과 "이 문서는 ~를 다룹니다" 두 문단은 지웁니다. "AI는 개발자, 나는 기획자"는 머리 표 "담당" 칸과 개요 한 문장으로.
- 개요 끝에 "핵심 / 부딪힌 문제 / 이렇게 풀었다" 표를 둡니다.

**전략 3. "플레이" 장을 새로 만들어 용어와 한 판의 흐름을 먼저 보여 준다** (원칙 3·17)
- 등장 오브젝트 그림 1장 + ①~⑦ 표(눈덩이, 눈 구역, 눈더미, 통나무, 목표 펭귄, 보스 펭귄, 열기 원·착지 표시).
- 세 스테이지를 "위 칸 이름 / 가운데 화면 / 아래 한 줄"의 3칸 표로. 지금 1.2 표의 긴 칸은 여기서 한 줄로 줄어듭니다.

**전략 4. 결정은 질문형 제목 + 표 1 + 문단 1** (원칙 11·13)
- "고민과 선택 ①~④" 번호와 ✅ 열 머리는 그대로 두되(이미 표 1 + 문단 형태), 제목을 질문으로 바꿉니다.
  - 4.2 → "부서지는 느낌을 어디까지 만들 것인가"
  - 4.3 → "부술 수 있다는 것을 어떻게 알릴 것인가"
- 숨어 있던 결정 하나를 꺼냅니다: 3.1 ⑥ "세 스테이지를 키우기 하나로 묶을 것인가"(1스테이지 작게 유지 vs 키우기 통일). 지금은 문단 속에 묻혀 있습니다.

**전략 5. 모든 절을 그림으로 열고, 프롬프트는 인용 하나로만 보여 준다** (원칙 7·19)
- 이미지 자리를 절 맨 앞으로 옮기고 캡션은 바로 아래 기울임 한 줄.
- 같은 대화를 인용 + 캡처로 두 번 보여 주지 않습니다. 인용을 남기고, 캡처는 **인용으로 옮길 수 없는 것**만 남깁니다(AI 후보 열 가지 목록, 기획서 화면, 인스펙터).
- "**왜 이렇게 요청했나**" 라벨은 없애고, 요점 bullet 2~3개로 절을 닫습니다.

**전략 6. 표 칸은 짧게, "~다"나 명사로** (원칙 14·15·16)
- 3.5 진단 표: 칸은 "공이 멈추지 않는다", "감속값이 0이다"처럼. 수치(4.2 > 3.2, 1.4 → 0.2)는 표 아래 문장으로.
- 3.2 보스 표: "내 답" 칸의 두 문장을 키워드로 줄이고, 긴 이유는 표 아래 bullet로.
- 5.2 As-Is/To-Be 표: "계기" 칸의 긴 인용은 짧게 자르고, 꼭 남길 인용은 표 아래로.

**전략 7. 문제는 한 장에, 회고는 결정을 하나의 질문으로 묶는다** (원칙 5·6)
- 트러블슈팅을 독립 장으로. `**문제**`·`**원인**` 라벨 대신 Super Phage 6장처럼 의도/문제/해결 그림 표 + 문단.
- 회고에 결정 묶음 표를 둡니다. 묶는 질문 후보:
  - **A. "검증에 필요한 만큼만 만들었는가"** — 대화 분리, 코드 안 보기, 파괴 연출, 색 표시, 키우기 통일이 모두 "속도를 얻고 무엇을 대가로 치렀나"로 답합니다.
  - **B. "무엇을 사람이 쥐고, 무엇을 AI에게 맡겼는가"** — 결정마다 사람이 쥔 것 / AI에게 맡긴 것 / 대가.
- 배운 점은 묶음 표에서 나온 한 문단만 남기고, 5.5의 반복 문장은 지웁니다.
